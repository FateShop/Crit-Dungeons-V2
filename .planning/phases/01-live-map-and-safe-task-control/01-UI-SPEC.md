## Layout and Component Inventory

| Component | Contract | Source |
|-----------|----------|--------|
| Settings entry | New map feature named **Dungeon Map Popup**, with **Popup Key** default **M**, under **Crit Addons** in Noamm's existing menu. Reuse configurable/savable KeybindSetting; show the actual current binding in hints. | CORE-03, MAP-02; routine naming delegated |
| Popup shell | Centered medium panel with gameplay visible on every side. At normal GUI sizes target 360 × 360 logical GUI pixels; cap each dimension at 75% of the available logical viewport, rounded down to a multiple of 4. Center again on resize/GUI-scale change. | D-11; dimensions delegated |
| Backdrop | Black at 35% opacity, no blur or opaque full-screen replacement. Panel fill is opaque for readable text. Native GUI must not pause the multiplayer world. | D-11; delegated |
| Header | **Dungeon Map**, left aligned, 16-unit horizontal inset; separate from the map by 8 units. | Delegated |
| Map viewport | Reuse public MapRenderer with real run data and `example=false`; uniformly fit its measured returned bounds inside remaining panel space. No stretching, clipping, copied tiles, independent labels or example preview. Honor extra returned height even when extra information is suppressed. | MAP-01; exact renderer findings in RESEARCH |
| Footer | Two static wrapped lines: current binding's close hint and Esc meaning; then **Room actions are unavailable in this version.** No running/paused/resuming status row. | D-08, D-12 |
| Empty content | Replace only the map viewport with contextual copy below. Keep header and key hints. No fabricated diagram, skeleton rooms, progress percentage or countdown. | MAP-01 |
| Notifications | Existing NotificationManager for named missing prerequisites and fatal explanations. No inline duplicate error engine or new toast visual. | CORE-04, D-13 |

Layout order is header → expanding map viewport → footer, with 16-unit panel padding and 8-unit gaps. Footer wraps before reducing map space. On small logical viewports use 8-unit padding, 4-unit gaps and the compact type role. Fit the map to the remaining rectangle with aspect ratio preserved; never enlarge the panel to full screen. If no positive map rectangle remains, show **Increase the window size or lower GUI Scale to view the map.** and preserve keyboard exit. Test this fallback rather than cropping controls. No popup animation, pulsating accents or decorative artwork is required.

| lg | 24 | Empty-state heading/body separation where space permits |

Exceptions: Noamm map geometry, label spacing, settings controls and notification spacing remain renderer-owned. Center coordinates, measured font widths and uniform map-fit factors may be fractional; do not snap internal room positions to this scale.

## Typography

Three sizes and two semantic weights for new chrome. Reuse the existing Noamm font and supported regular/bold treatment; do not ship a font to obtain numerical weights. Fit measured glyph height through the existing rendering scale rather than assuming Minecraft's native font is 16 pixels tall. The numbers are intended logical line-box font sizes, not claims about an inspected dependency font asset.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16 | regular (400 semantic) | 1.5 / 24 units |
| Label / compact body | 12 | regular (400 semantic) | 1.5 / 18 units |
| Heading | 20 | bold (700 semantic) | 1.2 / 24 units |

Use label size for persistent keyboard hints and unavailable-action copy; body for empty-state explanations; heading for the popup title and empty-state title. No extra display size. Noamm room labels and its menu/toast typography are inherited exceptions and must not be rescaled individually or restyled to satisfy these wrapper tokens. Wrap explanatory text by measured available width; do not truncate key names or corrective actions. Use existing supported key-name localization, including an unbound key's actual representation.

## Color

60/30/10 describes the intended hierarchy of new chrome, not room colors or a pixel-count quota. Defaults are selected under the user's cosmetic delegation; no claim is made that these are exact Noamm theme constants.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#18181B` | Panel body and opaque text backgrounds |
| Secondary (30%) | `#27272A` | Header/footer support surfaces |
| Accent (10% maximum) | `#A78BFA` | Current popup key token and existing native keyboard-focus indication when applicable |
| Destructive | `#F87171` | Esc cancellation wording only; retain explicit text meaning |
| Primary text | `#FAFAFA` | Title and body |
| Secondary text | `#D4D4D8` | Footer and supporting instructions |

Accent reserved for: the actual popup-key token and focus indication; never room fills, discovery highlights, all settings, or status pulses. Noamm's own map colors, completion markers, player markers, room identities, unknown-state rendering and notification error colors remain untouched. Do not dim or disable the live map merely because room actions are unavailable. Use textual error/unavailable explanations; color alone must never convey the distinction. Retain readable text over opaque chrome and check contrast in screenshots at supported GUI scales.

## Copywriting Contract

| Element | Copy / behavior |
|---------|-----------------|
| Primary action | **Open Dungeon Map** — the purpose of the configurable Popup Key; no additional button is required |
| Popup title | **Dungeon Map** |
| Close hint | **{Popup Key}: Close map · Esc: Stop automation and clear queued work** |
| Unavailable actions | **Room actions are unavailable in this version.** Static footer; no enabled travel/clear/secret controls |
| Outside dungeon heading | **No dungeon map** |
| Outside dungeon body | **Enter a dungeon to view Noamm's available map information.** |
| No known tiles heading | **No map information yet** |
| No known tiles body | **Noamm has not supplied map information for this run. The map updates as information becomes available.** |
| Partial discovery | Render only actual Noamm information; do not show a whole-map loading state while some real map data exists |
| Missing prerequisites toast title | **Dungeon Map Popup** |
| Missing prerequisites toast body | **Enable {disabled prerequisite list} in Noamm's Dungeon Map settings, then open the map again.** List actual disabled names among **Dungeon Map**, **Map Enabled**, **Cheater Map**; when Dungeon Map itself is disabled say **Enable Dungeon Map in Noamm, then open the map again.** Do not change those settings automatically. |
| Fatal error toast title | **Crit Addons stopped** |
| Fatal error toast body | **{Concrete reason}. {Actionable correction}. Current work was cleared.** Add an actual diagnostic report location only when one was successfully written. |
| Destructive confirmation | **Stop automation and clear queued work**: Esc acts immediately, without confirmation, in gameplay and with the popup open. This is emergency cancellation. No confirmation modal and no persistent mode-setting change. |
| Size fallback | **Increase the window size or lower GUI Scale to view the map.** |

Do not emit notifications for ordinary manual-input or GUI pause/resume, including opening/closing this popup. Required dependency/fatal notifications remain. Deduplicate a held/repeating opening key so it cannot flood toasts or flicker the popup. Never label Esc as simply **Close**; closing by the popup key and stopping by Esc have different effects. Do not claim **all rooms discovered**, **optimal**, **verified**, **task complete** or **released** without corresponding evidence. No restart/resume/queue buttons are introduced in this phase.

## Interaction and State Contract

| Trigger / state | Required outcome |
|-----------------|------------------|
| Popup key in gameplay | Toggle once per genuine press; default M. Opening checks prerequisites without enabling them. If prerequisites are missing, use the named Noamm toast and do not display fabricated/preview content. |
| Popup key with this popup open | Close popup without cancelling tasks. Remove only this GUI's pause reason; automatic resumption requires all other reasons cleared and actual-state reevaluation. |
| Opening another GUI | Preserve existing screen/input behavior. Do not hijack typing or a text field with the map hotkey; key matching must distinguish this popup from unrelated GUIs. |
| Popup open | General GUI pause applies to coordinated movement/combat. The map continues receiving actual Noamm discovery updates. Do not freeze the scanner or multiplayer simulation. |
| Left / Ctrl-left / Shift-right in Phase 1 | Do not enqueue travel, combat or secrets, invoke LeapMenu teammate behavior or simulate success. Keep popup open. Static unavailable copy explains the release boundary. Later phases retain the approved keep-open-after-dispatch contract. |
| Esc anywhere, including popup | Coordinator cancels execution/calculation, clears pending work and releases Crit-owned controls. With popup open, close it as normal screen dismissal in the same event; closing cannot restart the stopped session. Do not swallow Esc before cancellation observes it. |
| Manual input | Never block the player's input. Temporarily freeze automated movement/combat; preserve work; resume silently after genuine input ends and all other pauses clear, with actual-state reevaluation. Automation-generated input must not trigger this pause. |
| Death / revival | Preserve work while dead; revival reevaluates/replans and resumes only after all pauses clear. No popup or toast spam for routine transitions. |
| Esc / fatal stop | Persistent mode choice stays enabled. Same-run passive validity checks and screen closure cannot restart it; deliberate off/on or a genuinely new valid dungeon run can rearm according to D-03. No automatic-mode feature is advertised as implemented in Phase 1. |
| Boss entry / run end / exit / disconnect | Terminate and clear run work; clear old-run popup/map references so stale room information is never shown as current. Preserve user settings. No boss combat and no carry-over queue. Do not forcibly close an unrelated GUI. |
| Relaunch | Restore only Noamm-managed configuration/binding and eventual enabled mode selection; no popup-open state, task queue or old run execution. |

Map geometry, discovery, identities and transforms belong to Noamm. Use its current renderer/model each frame or through its supported update path, not a separately maintained room model. Do not render `example=true` as a fallback. Unknown rooms remain exactly as Noamm presents or omits them. New popup input must not leak room clicks into world item use/attacks, and must not globally block manual gameplay input when the popup is closed.

## Implementation and Visual Acceptance

1. Verify Crit Addons category placement, persistent rebinding and one-toggle-per-press behavior. Test default M, rebound key, unbound setting, key repeat and typing in unrelated screens.
2. Capture actual popup screenshots on 26.2 at normal and small windows and multiple GUI scales. Confirm centered medium bounds, visible game perimeter, complete returned map bounds, wrapped readable hints and size fallback. Inspect with Noamm extra-map-info setting both on and off.
3. Compare the popup against Noamm's actual live map: colors, room identities, discovery updates and unknown information must agree. No preview layout outside a run; no old-run information after lifecycle termination. Exercise applicable normal/master floor coverage rather than extrapolating one floor.
4. Verify disabled prerequisites individually and together, exact names in existing toasts and no key-repeat flooding. Verify fatal explanations and successfully created report links only when applicable.
5. In a controlled coordinated task session test M open/close preserving work, Esc with map open cancelling/clearing, independent GUI/manual/death pauses, silent resume, actual-state revalidation, same-run stop latch and fresh-run rearm. Confirm unrelated Noamm work survives Crit cancellation. Controlled tasks do not complete later travel/combat/secrets features.
6. Test inactive room-action combinations leave popup open and never execute/claim later capabilities. Verify Esc remains responsive and frame/client-thread constraints are respected during discovery updates.
